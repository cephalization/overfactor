# Goals

The outcomes Overfactor is pursuing, in priority order. Not a task tracker, issue list, or changelog — see git history and any issue tracker for that.

1. ~~**Slice one — daemon → live sidebar.**~~ **Done 2026-08-15.** A standalone daemon receives events from the Claude Code hooks integration via the typed SDK; the Electron app shows live sessions with title, agent, lifecycle state (working/idle/blocked), and live diff stats, plus repo tracking from the GUI and a read-only session detail pane. Verified against a real `claude` session.
2. ~~**Pi integration**~~ **Done 2026-08-15.** A Pi package installed user-level (`overfactor install pi`) maps native session, prompt, agent, tool, settled, and shutdown events onto the shared SDK and reports them to the daemon from every tracked repo, without affecting Pi when Overfactor is unavailable.
3. **Curated review** — intent-grouped review of a CR's diff, generated by an agent through the harnesses Overfactor already integrates (engine invocations live in the integration packages, maintained like the plugins). Done when: a review generates automatically on PR detection (gh→octokit) and on demand at any time (pre-PR included); regeneration is diff-aware — unchanged groups and their reviewed state survive; defaults (auto-triggers, engine/model selection such as "reuse the session's agent" or a pinned engine) are configurable in a settings page; keyboard-first navigation.
4. **Create sessions from Overfactor** — a "New session" flow that creates a per-session `git worktree` for a chosen repo/branch/agent and starts the conversation (terminal handoff first; daemon-owned headless sessions where a harness supports it, via a `start-session` capability). Retires the shared-worktree diff conflation from slice one.
5. **macOS menu bar item** — Tray presence surviving window close: daemon status at a glance (working/blocked counts), start/stop daemon, jump to recent sessions (focuses the window and selects the session).
6. **Sandboxes** — CR branch running in Docker behind Caddy at a stable `cr-N.<repo>.localhost` domain. Run config discovered per repo (`.overfactor/sandbox.json` → devcontainer → compose → fallback); routes managed live through Caddy's admin API; start/stop and the sandbox URL surfaced on the CR.
7. **Team sync** — live-share style session sharing (architecture TBD; plan for a sync engine + server process).

Change Request foundations (branch-keyed grouping, pinning API, sidebar grouping) shipped 2026-08-15/16; the remaining CR piece — GitHub PR detection — lands as part of curated review's auto-trigger.
